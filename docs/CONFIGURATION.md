# Configuration

A self-hosted Hub is configured in two places:

| File | Holds | Changes take effect |
|---|---|---|
| `.env` (next to `docker-compose.yml`) | Secrets, the public address, ports, provider keys, the release to run | `docker compose up -d` |
| `config/legion.toml` | Rules for the whole Hub: limits, who may register, MCP servers installed for the owner | `docker compose restart backend` |

Both are optional to edit: the installer writes working files. An invalid
`legion.toml` (unknown key, bad value) **stops the Hub at start** with a message
that names the key, rather than being ignored.

## `.env`

`.env.example` has a comment on every line; this is the same list by purpose.

### Secrets (generated by the installer)

| Variable | Used for |
|---|---|
| `POSTGRES_PASSWORD` | The database password. Changing it after the first start also needs `ALTER USER` in the database |
| `SECRET_KEY` | Signs login sessions. Changing it signs everybody out |
| `WORKSPACED_TOKEN` | The Hub ↔ room daemon |
| `MCP_HOST_TOKEN` | The Hub ↔ personal MCP supervisor |
| `MCP_GATEWAY_TOKEN` | The Hub ↔ MCP gateway |

Each service refuses requests when its token is empty, so a missing value turns a
feature off rather than opening it. Never reuse one value for two tokens.

The key that encrypts the secrets the Hub *stores* for you (provider keys, room
secrets) is not in `.env`: it is generated once into the Docker volume
`legion_legion_secrets`. Back that volume up ([INSTALL.md](INSTALL.md#backups)).

### Address and ports

| Variable | Default | |
|---|---|---|
| `HUB_PUBLIC_URL` | `http://localhost:8080` | The address in the browser's bar, exactly. Sign-in redirects and links use it |
| `LEGION_BIND` | `127.0.0.1` | The interface the Hub listens on. `0.0.0.0` makes it reachable from your network |
| `LEGION_PORT` | `8080` | The port on that interface |
| `HUB_DOMAIN` | – | With the `caddy` profile: the domain to get a certificate for |
| `COMPOSE_PROFILES` | – | `caddy` to start the HTTPS proxy |

### Release

| Variable | Default | |
|---|---|---|
| `LEGION_VERSION` | `latest` | The image tag to run, for example `v0.1.0` |

### Model providers

`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `OPENROUTER_API_KEY` are fallbacks for every
user. Each user can add their own in Settings, and a key a user adds is stored
encrypted with the keyring.

### Other

| Variable | Default | |
|---|---|---|
| `LEGION_REGISTRATION` | from `legion.toml` | `closed`, `invite` or `open`; wins over the file |
| `LEGION_OWNER_EMAIL` | – | For a database that had users before owners existed: the account that becomes the owner |
| `LEGION_SOURCE_URL` | the public repository | The "Source code" link. If you run a modified Hub, point it at your source (AGPL-3.0 section 13) |
| `MARKET_ENABLED` | `false` | See [Legion Market](#legion-market) |
| `DOCKER_SOCKET` | `/var/run/docker.sock` | The socket the room daemon and MCP supervisor use |
| `WORKSPACE_TMP_MB` | `512` | Size of `/tmp` in each room container |
| `MCP_GATEWAY_REQUIRE_HTTPS` | `true` | Whether MCP servers added by link must use HTTPS. Private and metadata addresses are refused either way |
| `MCP_GATEWAY_MEM_LIMIT` | `512m` | Memory ceiling of the gateway container |
| `LEGION_LIMIT_<KEY>` | – | A limit from the table below, for example `LEGION_LIMIT_MAX_RUNNING=8` |
| `LEGION_CAPACITY_<KEY>` | – | A server-wide limit, see [`[capacity]`](#capacity), for example `LEGION_CAPACITY_MEMORY_MB=3072` |

## `config/legion.toml`

The installer copies the annotated example, [`hub/legion.example.toml`](../hub/legion.example.toml);
every key in it is commented out and shows its default. Uncomment what you want
to change. There are four sections.

### `[limits]`

Apply to every user of this Hub. **By default there are no limits** except two that
must be finite because rooms are scheduled against them: `max_running` (rooms
running at the same time per user, default 5) and `mcp_personal_max_running`
(default 3).

A number is a whole number from 0, or the word `"unlimited"`. Each key can also be
set in `.env` as `LEGION_LIMIT_<KEY>` (upper case), and the variable wins over the
file. The example file documents all keys: rooms (`max_rooms`, `max_running`,
`monthly_hours`, memory and storage per room and per user), personal MCP servers
(`mcp_personal_*`), skills (`skill_package_max_mb`, `skills_storage_mb`) and
`link_mcp_max`.

### `[capacity]`

Limits for the whole server, all users together; `[limits]` is per user. **By
default there are none.** Set them when several people share the Hub, so that many
rooms starting at once are refused with "the server is at capacity, try again in a
few minutes" instead of the machine running out of memory.

```toml
[capacity]
max_workspaces = 3      # room workspaces running at the same time
memory_mb = 3072        # memory limits of running rooms and personal MCP servers, MB
```

`memory_mb` counts the memory *limits* given to rooms and personal MCP servers, not
what they use right now. Leave room for the Hub, the database and the operating
system. Each key can also be set as `LEGION_CAPACITY_<KEY>` in `.env`, which wins
over the file.

### `[registration]`

```toml
[registration]
mode = "closed"     # closed | invite | open
```

- The **first account** to register on an empty Hub becomes the owner, whatever the
  mode. There is exactly one owner.
- **`closed`** (default): nobody else can register.
- **`invite`**: the owner creates single-use invitation links in Settings →
  Profile (valid for 7 days, up to 30; each can be tied to an email address).
- **`open`**: anyone who can reach the Hub.

Everyone with an account gets a shell inside containers on this machine, so keep it
`closed` or `invite` unless the Hub is on a network you trust.

### `[[personal_mcp]]`

MCP servers installed for the owner when the Hub starts (and right after the owner
registers). One block per server, either a link or a Docker image:

```toml
[[personal_mcp]]
name = "docs"
url = "https://docs.example.com/mcp"

[[personal_mcp]]
name = "notes"
image = "ghcr.io/owner/notes-mcp:1.2"
port = 8000
```

A server whose name the owner already has is left alone, so changes made in Settings
stay. **Passwords and tokens never go in this file**: an unknown key (including
`token`) stops the Hub at start. Add credentials in Settings → Secrets and bind them
to the server.

## Legion Market

`MARKET_ENABLED=false` (the default) means this Hub never contacts Legion: the
catalogue is empty and there is no "link a Legion account". Set it to `true` to
browse and install from the Legion Market and to use Market tools (for example web
search) paid for with credits. Exactly what is sent then is in
[SELF_HOSTING_PRIVACY.md](SELF_HOSTING_PRIVACY.md).
